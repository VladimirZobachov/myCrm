# Design System — myCRM (ERP монтажных работ)

> Итерация 1 — документация и handoff.
> Источники: [`docker/design/tokens.json`](docker/design/tokens.json), [`docker/design/tailwind.config.js`](docker/design/tailwind.config.js), [`docker/design/ui-kit.html`](docker/design/ui-kit.html), [`docker/design/status-badges.html`](docker/design/status-badges.html).

## 1. Обзор

**Цель.** Заменить текущий UI (table-layout, шрифт 11px, «чистые» red/yellow/green) на mobile-first дизайн-систему для монтажников, которые в основном открывают CRM с телефона на объекте.

**Принципы:**

- **Mobile-first.** Базовый размер шрифта поднят до 14px, поля ввода — 16px (минимум, чтобы iOS не зумил при фокусе), тач-цели ≥ 44px. Интерфейс должен оставаться быстрым и читаемым на слабых мобильных сетях объекта.
- **Статусы — это бейджи, а не цвет текста/строки.** Каждый статус заявки — pill-бейдж с приглушённым семантическим цветом (не чистые red/yellow/green), чтобы снизить визуальный шум в списках и таблицах.
- **Карточки на мобильном, таблицы на десктопе.** Списки заявок отображаются как карточки (`.card`) на узких экранах и как таблица (`.dtable`) на широких — не наоборот. Карточка группирует то, что в таблице размазано по колонкам (объект, бригада, статус, сумма).
- **Мягкие тени вместо тяжёлых границ.** Карточная структура подчёркивается тенями (`shadow-sm/md/lg`), а не частоколом бордеров, как в UI 1.0.

## 2. Токены

Единый источник — `docker/design/tokens.json`, 1:1 смапплен в `tailwind.config.js` (`theme.extend`). **При изменении токенов обновляй оба файла синхронно** — автогенерации пока нет.

### Цвета — primary

| Токен | Hex | Назначение |
|---|---|---|
| `primary.50`–`primary.900` | `#eef2ff` → `#312e81` | Шкала индиго |
| `primary.DEFAULT` / `primary.600` | `#4f46e5` | Основной акцент: кнопки, ссылки, активные табы, фокус-рамки |

Индиго выбран вместо банального синего — достаточно «технологичный» для B2B-инструмента, но не сливается с семантическими red/yellow/green.

### Цвета — neutral (slate, не чистый серый)

| Токен | Hex | Назначение |
|---|---|---|
| `neutral.surface` | `#ffffff` | Фон карточек, инпутов, модалок |
| `neutral.surface-alt` | `#f8fafc` | Фон страницы, hover строк таблицы |
| `neutral.surface-sunken` | `#f1f5f9` | «Утопленные» области: disabled-инпуты, код |
| `neutral.ink` | `#0f172a` | Основной текст |
| `neutral.ink-secondary` | `#334155` | Вторичный текст (тело карточки) |
| `neutral.muted` | `#64748b` | Подписи, плейсхолдеры, иконки |
| `neutral.muted-2` | `#94a3b8` | Ещё более приглушённый текст/иконки |
| `neutral.border` | `#e2e8f0` | Стандартная граница |
| `neutral.border-strong` | `#cbd5e1` | Граница инпутов, акцентная граница |

### Цвета — semantic (статусы, алерты)

Каждый цвет имеет `DEFAULT` (текст/иконка), `bg` (заливка бейджа/строки), `border` (рамка):

| Токен | DEFAULT | bg | border | Смысл |
|---|---|---|---|---|
| `success` | `#16a34a` | `#f0fdf4` | `#bbf7d0` | Выполнено, успех |
| `warning` | `#d97706` | `#fffbeb` | `#fde68a` | В ожидании, требует внимания |
| `danger` | `#dc2626` | `#fef2f2` | `#fecaca` | Ошибка, просрочено, удаление |
| `info` | `#0284c7` | `#f0f9ff` | `#bae6fd` | Принят, информационный статус |

`neutral` (для статуса «Архив») отдельного семантического токена не имеет — берётся из нейтральной гаммы: `#64748b` / `#f1f5f9` / `#cbd5e1` (см. `status-badges.html`).

### Типографика

Базовая шкала — модульная, шаг ~1.2. Шрифт: `Inter, -apple-system, 'Segoe UI', Roboto, sans-serif` (моно — `'JetBrains Mono'`).

| Токен | Размер / line-height | Вес | Когда использовать |
|---|---|---|---|
| `xs` | 12px / 16px | — | Метки бейджей, аптайп-надписи |
| `sm` | 13px / 18px | — | Вторичный текст, подписи полей |
| `base` | 14px / 20px | — | Основной текст интерфейса (было 11px) |
| `md` | 16px / 24px | — | **Текст в полях ввода** (мин. для мобильных, чтобы избежать zoom на iOS) |
| `h4` | 18px / 24px | 600 | Заголовок карточки, диалога |
| `h3` | 20px / 28px | 600 | Заголовок секции |
| `h2` | 24px / 32px | 700 | Заголовок раздела |
| `h1` | 30px / 38px | 700 | Заголовок страницы |

Веса: `regular` 400, `medium` 500, `semibold` 600, `bold` 700.

### Отступы (spacing)

Шкала 4px, кратна тач-цели 44–48px (`space-12`):

| Токен | Значение |
|---|---|
| `1` | 4px |
| `2` | 8px |
| `3` | 12px |
| `4` | 16px |
| `6` | 24px |
| `8` | 32px |
| `12` | 48px |

### Радиусы

| Токен | Значение | Применение |
|---|---|---|
| `sm` | 4px | Бейджи, мелкие элементы |
| `md` | 8px | Кнопки, инпуты, dropdown |
| `lg` | 12px | Карточки, таблицы, модалки |
| `full` | 9999px | Pill-бейджи |

### Тени

| Токен | Значение | Применение |
|---|---|---|
| `sm` | `0 1px 2px rgba(15,23,42,.06)` | Карточки, таблицы, кнопки |
| `md` | `0 4px 8px rgba(15,23,42,.08), 0 1px 2px rgba(15,23,42,.06)` | Dropdown-меню |
| `lg` | `0 12px 24px rgba(15,23,42,.12), 0 4px 8px rgba(15,23,42,.06)` | Модальные диалоги |

### Motion

Короткие длительности — интерфейс должен ощущаться быстрым на слабых мобильных сетях/устройствах на объекте.

| Токен | Значение | Применение |
|---|---|---|
| `duration.fast` | 100ms | Hover, focus, нажатие кнопки |
| `duration.normal` | 180ms | Появление модалки |
| `duration.slow` | 280ms | Крупные переходы |
| `easing.standard` | `cubic-bezier(0.4, 0, 0.2, 1)` | По умолчанию |
| `easing.emphasized` | `cubic-bezier(0.2, 0, 0, 1)` | Акцентные переходы (открытие модалки) |

## 3. Компоненты

Живые примеры и разметка — в [`docker/design/ui-kit.html`](docker/design/ui-kit.html) и [`docker/design/status-badges.html`](docker/design/status-badges.html).

| Компонент | Варианты | Когда использовать |
|---|---|---|
| **Кнопка** (`.btn`) | `primary`, `secondary`, `outline`, `ghost`, `danger`; размеры `sm` / default (38px) / `lg` (46px) | `primary` — одно главное действие на экране; `secondary`/`outline` — второстепенные действия; `ghost` — действия внутри карточек/таблиц (Отмена и т.п.); `danger` — необратимые/деструктивные действия (удаление) |
| **Инпут** (`.input`) | text, select, textarea, checkbox, radio; состояния default / focus / `is-error` / disabled | Все формы. Высота полей 40px, текст 16px (`fs-md`) — не занижать, иначе зум на мобильном Safari |
| **Карточка** (`.card`) | header + body + footer | Основной контейнер заявки на мобильном; блоки на дашборде; детальная карточка объекта |
| **Таблица** (`.dtable`) | header + строки с hover | Списки заявок на десктопе/широких экранах. На мобильном — заменяется карточками, не сжимается по горизонтали |
| **Диалог** (`.overlay` + `.dialog`) | overlay + анимация появления | Подтверждение удаления, короткие формы, не полноценные страницы. Закрытие по Esc/клику вне/крестику |
| **Бейдж** (`.badge`) | `--default` (заливка, белый текст), `--subtle` (заливка+рамка в тон, по умолчанию в таблицах/карточках), `--outline` (только рамка) | Статусы заявок и монтажа — всегда бейдж, никогда просто цветной текст |
| **Dropdown** (`.dropdown` + `.dropdown-menu`) | пункты + разделитель + `danger`-пункт | Контекстные действия над заявкой/строкой («Действия ▾») |
| **Табы** (`.tabs`) | список табов + панели | Переключение разделов внутри карточки заявки (Информация / Документы / История) |

## 4. Статусы заявок

Маппинг статуса заявки на семантический цвет и бейдж (см. [`status-badges.html`](docker/design/status-badges.html)):

| Код | Статус | Семантика | CSS-класс | Токен |
|---|---|---|---|---|
| `1` | В ожидании | warning | `badge-warning` | `--c-warning` |
| `2` | Принят | info | `badge-info` | `--c-info` |
| `3` | Выполнено | success | `badge-success` | `--c-success` |
| — | Архив | neutral | `badge-neutral` | `--c-neutral` (берётся из нейтральной гаммы, отдельного semantic-токена нет) |

По умолчанию в таблицах и карточках используется вариант **`badge--subtle`** (заливка + рамка в тон). Вариант `--default` (насыщенная заливка) — для акцентов, где важно выделить статус сильнее (например, шапка карточки заявки). `--outline` — компактные списки/легенды.

## 5. Использование в коде

Токены смапплены в `theme.extend` в [`docker/design/tailwind.config.js`](docker/design/tailwind.config.js) — используем стандартные Tailwind-утилиты с именами токенов, а не сырые hex/px.

```jsx
// Кнопка — primary action
<button className="bg-primary-600 hover:bg-primary-700 text-white
                    h-[38px] px-4 rounded-md shadow-sm font-medium text-base">
  Открыть заявку
</button>

// Инпут с ошибкой
<input className="w-full h-10 px-3 rounded-md border border-danger text-md
                   focus:outline-none focus:ring-[3px] focus:ring-danger-bg" />

// Карточка заявки (мобильный список)
<div className="bg-neutral-surface border border-neutral-border rounded-lg shadow-sm">
  <div className="p-4 border-b border-neutral-border flex justify-between">
    <h3 className="text-h4 font-semibold">Заявка ORD-10432</h3>
    <span className="badge badge--subtle badge-warning">В ожидании</span>
  </div>
  <div className="p-6 text-neutral-ink-secondary">...</div>
</div>

// Бейдж статуса — маппинг из раздела 4
<span className={`badge badge--subtle badge-${statusToVariant[order.status]}`}>
  {statusToLabel[order.status]}
</span>
```

Классы `.btn`, `.input`, `.card`, `.dtable`, `.badge`, `.dropdown`, `.tabs` из `ui-kit.html` — референс разметки/поведения (включая JS для dialog/dropdown/tabs), при переносе на Next.js — переиспользовать структуру и заменить CSS-переменные на Tailwind-классы токенов.

## 6. Чек-лист перед сдачей UI

- [ ] Тач-цели (кнопки, чекбоксы, пункты меню, строки таблицы на мобильном) — **не меньше 44×44px**.
- [ ] Текст в полях ввода — **не меньше 16px** (`fs-md`), иначе зум на iOS Safari.
- [ ] Контраст текста к фону соответствует WCAG AA (обычный текст ≥ 4.5:1, крупный ≥ 3:1) — особенно для `muted`/`muted-2` текста на `surface-alt`.
- [ ] Статус заявки показан **бейджем** (`.badge`), а не цветом текста строки или голой заливкой ячейки.
- [ ] Список заявок на мобильном — **карточки**, не горизонтально скроллящаяся таблица.
- [ ] Все интерактивные элементы имеют видимое `:focus-visible` состояние (не убирать `outline` без замены).
- [ ] Цвета, отступы, радиусы, тени, шрифты — только из токенов (`tokens.json` / `tailwind.config.js`), без хардкода hex/px «на глаз».
- [ ] Диалоги закрываются по Esc, клику вне и явной кнопке — проверено на мобильном (без hover-состояний).
- [ ] Длительности анимаций — из `motion.duration` (100/180/280ms), не длиннее — интерфейс должен ощущаться быстрым на слабых сетях объекта.
