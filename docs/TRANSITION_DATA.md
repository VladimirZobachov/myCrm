# Переходный период: синхронизация данных myCRM

**Дата:** 12.08.2026
**Статус:** документ для перехода (strangler fig)

## 1. Общая БД

Обе системы пишут в **одну БД** `firmaacru_crm` (MySQL 5.7):

| Система | Доступ | Порт |
|---------|--------|------|
| Legacy (PHP 7.4) | mycrm_db контейнер | 3306 (внутренний) |
| Новая (Laravel 12) | mycrm_db контейнер | 3306 (внутренний) |

⚠️ Порт 3306 НЕ публикуется наружу (после ransomware 11.08.2026). Контейнеры общаются по docker-сети `mycrm_default`.

| Компонент | Legacy | Новая | Конфликт? |

## 3. Отключение email в legacy для мигрированных ролей

**Проблема:** если пользователь мигрирован на v2 (`users.migrated_to_v2 = 1`), а legacy всё ещё отправляет ему письма — дубли (legacy + новый Laravel).

**Файл:** `/tmp/mycrm/index.php` — 7 точек отправки через `$mailer->Send()`:

| Строка | Функция | Тема письма | Получатель |
|--------|---------|-------------|------------|
| ~262-270 | add() | «Заявка на монтаж №» | создатель/админы |
| ~399-407 | add() (назначение) | «Вам назначена заявка №» | монтажник |
| ~435-439 | save() | «Редактирование заявки №» | владелец/админ |
| ~482 | updateComment() | «Комментарий {for_name}» | админ/менеджер |
| ~521 | updateComment() | «Измененен комментарий» | админ |
| ~552 | updateStatus() | «Изменения статуса заявки» | владелец/монтажник |
| ~654 | register() | «Регистрация в системе заказов» | новый юзер |

**Как отключить (когда будет внедряться):** перед каждым `$mailer->Send()` добавить проверку получателя:

```php
// Пропускаем email, если получатель уже мигрирован на v2 (дубли писем)
$migrated = SELECT migrated_to_v2 FROM users WHERE id = $recipient_id; // через db.class
if ($migrated == 1) { /* skip send */ }
```

Либо на этапе перехода проще: отключить блоки `include_once(mailer.php)` целиком для мигрированных ролей — письма за них шлёт новая система.
