# Переход на новую систему (strangler fig) — пошагово

**Дата:** 12.08.2026
**Цель:** перевести пользователей myCRM с legacy (PHP 7.4) на новую (Laravel + Next.js) роль за ролью, без потери данных и без дублей писем.

## Правило

**Роль за ролью. Без прохождения критериев перехода — не расширяемся на следующую роль.**

## График переключения (план по ролям)

| Этап | Роль | type_user | Критерии перехода (все обязательны) | Ориентир |
|------|------|-----------|--------------------------------------|----------|
| 0 | Пилот (1-2 монтажника вручную) | 3 | Логин, список, создание заявки, фото с телефона, 1 письмо (не дубль) | День 1 |
| 1 | Монтажники (все) | 3 | Этап 0 + 100% мигрированных логинятся, 0 ошибок в логах за 3 дня | День 3-5 |
| 2 | Менеджеры | 2 | Этап 1 + экспорт Excel работает, комментарии/статусы в обе стороны | День 7-10 |
| 3 | Админы | 1 | Этап 2 + панель пользователей, миграция-метрики, backup подтверждён | День 12-14 |
| 4 | Выключение legacy | — | Этапы 0-3 + 7 дней без обращений в поддержку о потерянных данных | День 21+ |

## Критерии расширения (детально)

Перед переходом на следующую роль проверить:

### Функциональные
- [ ] Логин/пароль (MD5→bcrypt rehash) — работает для всех мигрированных
- [ ] Список заявок: фильтры, сортировка, пагинация, архив
- [ ] Создание/редактирование заявки (все legacy-поля)
- [ ] Статусы (ждет/принят/готов), комментарии (модалка «⋮»)
- [ ] Загрузка фото с телефона (камера) + галерея
- [ ] Экспорт Excel (3 варианта, очередь для больших)
- [ ] Пользователи (только админ) + кабинет

### Технические
- [ ] Backend: 117+ тестов зелёные (phpunit)
- [ ] Frontend: 114+ тестов зелёные (vitest)
- [ ] Нет ошибок в laravel.log за 3 дня (кроме 401 от ботов)
- [ ] nginx error.log чист
- [ ] Панель /migration показывает корректные проценты

### Email
- [ ] Письма приходят РОВНО 1 раз (нет дублей legacy + новый)
- [ ] Legacy пропуск email для мигрированных включён (docs/TRANSITION_DATA.md §3)
- [ ] PHPMailer SMTP настроен (MAIL_HOST/USERNAME/PASSWORD в .env)

### Безопасность
- [ ] Порт БД не публикуется наружу
- [ ] APP_DEBUG=false на проде
- [ ] Токены: JWT httpOnly (не localStorage)

## Правило остановки (rollback)

При любом из условий — откатить флаг роли (`migrate:flag-role {role} --off`) и вернуть пользователей на legacy:
- Критическая ошибка, блокирующая работу > 30 минут
- Потеря данных (заявка создана в новой, пропала в legacy)
- Дубли писем не устранены за 1 день
- Метрика ошибок по роли > 1% запросов

## Порядок

### Шаг 1. Подготовка (однократно)

```bash
# 1. Применить миграции на БД
cd /tmp/mycrm/backend
php artisan migrate --force

# 2. Проверить, что новая система работает (health)
curl http://127.0.0.1:8000/api/health
curl http://127.0.0.1:3000/            # фронтенд
```

### Шаг 2. Подключить reverse-proxy

```bash
# 1. Скопировать конфиг (deploy/nginx/mycrm.conf)
sudo cp deploy/nginx/mycrm.conf /etc/nginx/conf.d/mycrm.conf

# 2. Выпустить сертификат
sudo certbot --nginx -d crm.vvebmaster.ru

# 3. Проверить и перезагрузить
sudo nginx -t && sudo systemctl reload nginx
```

Подробнее: `deploy/nginx/README.md`.

### Шаг 3. Переключить первую роль (например, монтажники, type_user=3)

```bash
cd /tmp/mycrm/backend

# Перевести всех монтажников на v2
php artisan migrate:flag-role 3 --on

# Проверить, кто мигрирован
php artisan tinker --execute="echo App\Models\User::migrated()->count();"
```

### Шаг 4. Критерии перехода (обязательно!)

- [ ] Все мигрированные пользователи могут залогиниться в новой системе
- [ ] Список заявок, создание, статусы, комментарии — работают
- [ ] Загрузка фото с телефона — работает
- [ ] Email-уведомления приходят ОДИН раз (не дубли)
- [ ] Ошибок в логах нет (laravel.log, nginx error.log)

### Шаг 5. Отключить email в legacy для мигрированных ролей

См. `docs/TRANSITION_DATA.md` §3 — 7 точек `$mailer->Send()` в `/tmp/mycrm/index.php`, добавить проверку `migrated_to_v2`.

### Шаг 6. Следующая роль

Повторить шаги 3-5 для менеджеров (type_user=2), затем админов (type_user=1).

## Точка невозврата

- После перевода ВСЕХ ролей: legacy можно выключать (остановить mycrm_web контейнер)
- До этого: legacy работает параллельно (обе пишут в одну БД)

## Риски

| Риск | Митигация |
|------|-----------|
| Дубли писем | Шаг 5 (пропуск email в legacy) |
| Конфликт id | Общий AUTO_INCREMENT — не конфликтуют |
| Потеря данных | Обе системы в одной БД |
| Пароли | MD5 → bcrypt ленивый rehash при логине |
